Magpie is a knowledge store built for AI agents and usable by humans. You write durable knowledge — prose, structured values, links, files — once, and agents retrieve it through search, references, and the Model Context Protocol. It's the shared memory layer your apps and agents delegate to instead of each rebuilding their own.

## What it gives you

- **Dual search** — semantic (vector embeddings) and keyword (Postgres full-text), combined with Reciprocal Rank Fusion so results are good whether the query matches by meaning or by exact term.
- **Knowledge entries** — Markdown with typed metadata, organized by [PARA](/concepts/entries) category and scoped by org / workspace / project.
- **Collections** — typed JSON key/value stores for structured context an agent resolves by key, not prose. See [Collections](/concepts/collections).
- **Links & references** — `[[wikilinks]]` between entries with backlinks, and `{{value references}}` that resolve at read time. See [Links](/concepts/links).
- **Attachments** — logos, screenshots, SQL snippets, PDFs owned by an entry, with stable handles. See [Attachments](/concepts/attachments).
- **Three surfaces** — a REST API, an [MCP server](/mcp/overview) for agents, and a [CLI](/cli/installation). Plus a management UI.

## What it isn't

Not an agent framework, not a chat-history memory system, not a general graph database. Magpie owns reusable, durable context — the things future agents or teammates should remember, search, cite, and reuse. Operational runtime state stays in your app's own database.
