---
title: REST API
description: HTTP endpoints for entries, search, KV stores, attachments, and bundles.
---

All endpoints are under `/api`. Authenticate with `Authorization: Bearer <token>` or a session cookie. Where relevant, requests accept `workspace` and `project` to scope. Interactive docs are served at `/docs` on a running server.

Multi-org users select their **active org** with the `X-Organization-ID` header — validated against membership, so naming an org you don't belong to returns `403`. See [Authentication & multi-tenancy](/reference/auth).

## Entries

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/entries` | Create an entry |
| `GET` | `/api/entries` | List / filter (`archived`, tags, workspace, project). `archived` is a boolean: omit for all, `false` for active only, `true` for archived only |
| `GET` | `/api/entries/{id}` | Get one |
| `PUT` | `/api/entries/{id}` | Update |
| `DELETE` | `/api/entries/{id}` | Delete |
| `POST` | `/api/entries/{id}/archive` | Archive |
| `POST` | `/api/entries/{id}/unarchive` | Restore an archived entry |
| `POST` | `/api/entries/merge` | Merge entries into one; sources are archived |
| `POST` | `/api/entries/bulk` | Rescope/retag many entries at once (dry-run by default) |
| `GET` | `/api/entries/{id}/links` | Outgoing links + backlinks |
| `POST` | `/api/entries/{id}/resolve` | Resolve `{{references}}` and `[[wikilinks]]` |
| `POST` | `/api/search` | Dual semantic + keyword search (excludes archived) |

Entry objects expose `archived_at` — a timestamp when the entry is archived, `null` when active. `POST`, `PUT`, `/api/search`, and `/api/entries/merge` accept `title`, `content`, `tags`, `source`, `workspace`, and `project`; there is no category field.

`POST /api/entries/bulk` takes `{ match, changes, dry_run }`. `match` (at least one of `workspace`, `project`, `tags`, `source` — never empty) selects entries; `changes` sets `workspace`/`project`, `add_tags`/`remove_tags`/`rename_from`+`rename_to`, or `clear` (e.g. `["project"]`). It updates matched rows **in place** (ids, links, and embeddings preserved) within the caller's own + active-org scope. `dry_run` defaults to `true` and returns `{ matched, sample, applied, updated }` without writing; setting it `false` applies the change and requires the `admin` role. See [Reorganizing in bulk](/concepts/bulk-operations).

## KV stores

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/kv` | List KV stores (each exposes `key_count`) |
| `POST` | `/api/kv` | Create a KV store |
| `DELETE` | `/api/kv/{store_id}` | Delete a KV store |
| `GET` | `/api/kv/{slug}/keys` | List keys (`{ store, pairs }`) |
| `GET` | `/api/kv/{slug}/keys/{key}` | Get a key |
| `PUT` | `/api/kv/{slug}/keys/{key}` | Set a key |
| `DELETE` | `/api/kv/{slug}/keys/{key}` | Delete a key |

Writes to a `repo`-canonical KV store are rejected (the bundle is the source of truth).

## Bundles (repo sync)

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/bundle/push` | Validate and apply a bundle. Aborts (422) on off-spec files or drift |

## Activity

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/updates` | Recent activity across the store, newest first (`workspace`, `project`, `limit` ≤ 100) |

Each event records what changed, when, and by whom. The log is **durable**: it survives overwrites and deletes, and covers entries, KV, attachments, merges, bulk edits, and bundle pushes — not just current row state. Events are visibility-filtered to the caller's active org plus the events they performed. Each item carries a back-compatible projection (`kind`, `action`, `title`, `entry_id`, `store`, `key`, `value_type`, `workspace`, `project`, `at`) alongside the full event shape (`id`, `subject_type`, `subject_id`, `subject_title`, `actor_user_id`, `actor_type`, `metadata`). See [Activity log](/concepts/activity).
