---
title: Staying coherent
description: How Magpie stops a knowledge store from fragmenting into near-duplicates and drift.
---

Every shared memory store rots the same way. Agents write the same fact under slightly different titles, the same value lands in two collections with different keys, and six months in nobody trusts what's canonical. Search still works — it just returns five near-identical answers.

Magpie treats coherence as a first-class job, defended at every layer: when an entry is written, when duplicates are found, when they're merged, and when collections are declared.

## Dedupe on write

A write can ask Magpie to **update the closest existing entry instead of creating a new one**. Pass `dedupe` and the server finds the nearest semantic match in scope; if it's close enough, that entry is updated in place rather than forked.

```bash
magpie write --title "Pricing decision" --file note.md --dedupe
```

Over [MCP](/mcp/tools), `write(dedupe=true)`; over [REST](/reference/api), `"dedupe": true` on `POST /api/entries`. This is the cheapest defense — it stops duplicates from being created in the first place.

## Find duplicates

For entries that already exist, `find_duplicates` clusters them by semantic similarity and returns groups that cover the same topic — consolidation opportunities you can review before merging.

```bash
magpie duplicates --workspace support
#   Cluster 1 (2 entries):
#     - Refund policy            (dist: 0.04)
#     - How refunds work         (dist: 0.04)
```

`threshold` is a cosine distance — **lower is stricter** (default `0.12`). Available as the `find_duplicates` MCP tool and `POST /api/entries/find-duplicates`.

## Merge with lineage

`merge` collapses two or more entries into one. You supply the synthesized title and content; the source entries are **archived with lineage** (not deleted), so the merge is auditable and reversible.

```bash
magpie merge <id-a> <id-b> --title "Refunds" --file merged.md
```

Merging requires the `editor` role and at least two sources. Available as the `merge` MCP tool and `POST /api/entries/merge`.

## Collections can't drift

Structured values get their own defense. A [collection](/concepts/collections) registry — the `_manifest.json` — declares the canonical stores, and Magpie refuses any store whose slug isn't declared or that near-duplicates an existing one (`Did you mean 'config'?`), **at push time and on live writes**. Repo-canonical stores reject agent writes entirely, so curated config stays pinned to git.

See [Anti-drift](/repo-sync/anti-drift) for the manifest in full.

## Why it matters

These aren't separate features so much as one principle: a knowledge store is only useful if it stays trustworthy. Dedupe-on-write prevents fragmentation, find/merge repairs it, and the collection registry stops it structurally — so what an agent reads back is one coherent source of truth, not a pile of near-duplicates.
