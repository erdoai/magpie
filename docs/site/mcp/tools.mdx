Every tool is scoped by the caller's org and role. Most accept `workspace` and `project` to narrow scope.

## Knowledge

### `search`
Semantic + keyword search across knowledge. Archived entries are excluded automatically.
**Key params:** `query`, `workspace`, `project`, `limit`.
**Returns:** ranked entries with scores.

### `read`
Read one entry by id.
**Params:** `id`, `resolved` (resolve `{{refs}}` and `[[links]]`, default false).
**Returns:** the entry, plus links, backlinks, and attachment summaries.

### `write`
Create a knowledge entry.
**Key params:** `title`, `content`, `tags`, `source`, `workspace`, `project`.

### `list_entries`
Browse and filter entries. Archived entries are flagged with `[archived]`.
**Key params:** `archived` (omit for all, `false` for active only, `true` for archived only), `tags`, `workspace`, `project`, `limit`.

### `archive`
Archive an entry. **Params:** `id`.

### `merge`
Merge several entries into one; the sources are archived. **Key params:** `source_ids`, target fields.

### `find_duplicates`
Find clusters of near-duplicate entries by semantic similarity. **Key params:** `threshold`, `limit`.

### `bulk_edit`
Rescope or retag many entries at once, in place (ids, links, embeddings preserved). Selects with `match_*` filters (at least one required) and applies `set_workspace`/`set_project`, `add_tags`/`remove_tags`/`rename_tag_from`+`rename_tag_to`, or `clear_project`. **Always preview with `dry_run` (default true) first; applying requires `admin`.** See [Reorganizing in bulk](/concepts/bulk-operations).

### `list_updates`
Recent activity across the store, newest first — what changed, when, and by whom. Durable: covers entries, KV, attachments, merges, bulk edits, and bundle pushes, and survives overwrites and deletes. **Key params:** `workspace`, `project`, `limit`. See [Activity log](/concepts/activity).

### `entry_history`
Previous versions of an entry, newest first — what it said before each meaningful edit (title/content/tags/source), with actor and time. The current version is what `read` returns. **Params:** `id`, `limit`.

## Links & references

### `list_links`
Outgoing links and backlinks for an entry. **Params:** `id`.

### `resolve_knowledge`
Resolve an entry's `{{value references}}` and `[[wikilinks]]` at read time, with a dependency list. **Params:** `id`.

## KV stores

### `kv_list`
List KV stores in scope. **Key params:** `workspace`, `project`.

### `kv_get`
Read a key (returns value + `value_type`). **Params:** `store`, `key`.

### `kv_set`
Write a typed pair. **Key params:** `store`, `key`, `value`, `value_type`, `create_store`.
Rejected for [repo-canonical](/repo-sync/kv) stores; refuses a near-duplicate new slug.

### `kv_delete`
Delete a key. **Params:** `store`, `key`.

## Attachments

### `upload_attachment`
Attach a base64 file to an entry. **Key params:** `entry_id`, `filename`, `data`, `role`.

### `list_attachments`
List attachments on an entry. **Params:** `entry_id`.

### `get_attachment`
Get attachment metadata and content/URL. **Params:** `id`.
